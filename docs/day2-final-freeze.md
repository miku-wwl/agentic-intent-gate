## Frozen architecture and contracts

`Intent → POST /api/runs → durable Run → PlanGenerating → ModelProvider → strict JSON/schema/semantic validation → trusted risk recomputation → PlanValidated → Ready or AwaitingApproval → local Approved/Rejected`.

Exactly eight persistent states remain: `IntentReceived`, `PlanGenerating`, `PlanValidated`, `Ready`, `AwaitingApproval`, `Approved`, `Rejected`, `PlanRejected`. The legacy `/api/plans` page/API is intentionally retained as stateless compatibility, not a second durable or execution architecture. Tool definitions supply validation metadata only; no tools execute.

SQLite `user_version=1` has exactly three STRICT tables: Runs, approval decisions and paired audit events. WAL, FULL synchronous, foreign keys, 250 ms busy timeout and short `BEGIN IMMEDIATE` writes remain frozen. Model/network I/O stays outside transactions. All four source JSON schemas remain unchanged and must match wheel resources.

Normal read path versions are 1→2→3→4 (`Ready`); write-risk paths reach `AwaitingApproval` at v4 and one `Approved`/`Rejected` at v5. GET, failed CAS, duplicate/stale decisions and converged recovery do not advance versions. Approval accepts only `decision`, `expected_version` and optional bounded `reason`; server CAS controls the immutable Plan/state/risk and server actor marker. UPDATE, decision INSERT and audit INSERT commit atomically; uncertainty returns a safe database error, never invented success or automatic replay. `LOCAL_USER` is not authenticated authorization. **Approved != Executed.**

Strict parsing, schema/semantic checks and independent trusted risk recomputation remain authoritative; JSON mode is not a substitute. At most one model call per planning operation, no retry/fallback, no client model/endpoint override. Prompt 5 performs zero live model calls.

Startup validates schema, integrity, stored Plans and linked audit/decision history before serving. Recovery rejects interrupted received/generating Runs with `RECOVERY_INTERRUPTED`, deterministically routes only committed `PlanValidated`, and preserves all other states. Repeated passes converge without version/event churn; recovery, GET and approval make zero model/tool calls. Corrupt/incompatible/future schemas fail closed without reset, migration guessing or in-memory fallback. Exactly one app process/worker per DB is supported, with its predecessor stopped before recovery.
