# v0.2.0 consumer handoff

Package: `agentic-intent-gate==0.2.0`, Python 3.13, MIT licensed. This is a Git release,
not a PyPI publication. The annotated `v0.2.0` tag identifies the immutable release;
its verified full commit pin is recorded in this document on `main` after tag creation.
A commit cannot embed its own SHA, so the final reference update is a separate documentation
commit without moving the release tag.

## Installation and public API

Resolve the annotated tag to its full commit before pinning, rather than using `main`:

~~~powershell
$releaseLine = git ls-remote https://github.com/miku-wwl/agentic-intent-gate.git 'refs/tags/v0.2.0^{}'
if (-not $releaseLine) { throw 'Verified v0.2.0 tag is required before upgrading' }
$releaseSha = ($releaseLine -split '\s+')[0]
uv pip install "agentic-intent-gate @ git+https://github.com/miku-wwl/agentic-intent-gate.git@$releaseSha"
~~~

Import `open_runtime` and `execution_budget_binding` from `agentic_intent_gate.runtime`.
The [complete executable API example](ADAPTER_GUIDE.md#supported-consumer-api) supplies
the provider, capability, registry, verifier, policy and private gate path. It demonstrates
the exact new calls:

~~~python
import asyncio
import json
from pathlib import Path
from tempfile import TemporaryDirectory

from examples.consumer.app import (
    ARGUMENT_SCHEMA, AuditExecutor, DeterministicProvider, provision, workflow,
)
from agentic_intent_gate.runtime import (
    BoundCapabilityAuthorization, CapabilityVerifier, ExecutableRegistry,
    ToolBinding, ToolCapability, open_runtime,
)

def host_configuration(directory, seconds):
    provision(directory, execution_timeout_seconds=seconds)
    binding = ToolBinding(**json.loads((directory / "identity.json").read_text("utf-8")))
    executor = AuditExecutor(directory / "effects.sqlite3", binding)
    verifier = CapabilityVerifier(
        (directory / "capability").read_text("ascii"), subject_id="consumer-operator",
        binding=binding, operations=("read", "admit", "authorize", "execute"),
    )
    return dict(
        gate_path=directory / "gate.sqlite3", provider=DeterministicProvider(),
        capability=ToolCapability(binding, "Append one audit entry", ARGUMENT_SCHEMA),
        registry=ExecutableRegistry(executor, binding=binding), verifier=verifier,
        policy=BoundCapabilityAuthorization(verifier, policy_revision="consumer-policy-v1"),
        predecessor_stopped=True,
    )

with TemporaryDirectory(prefix="aig-budget-example-") as root:
    default_directory = Path(root) / "default"
    with open_runtime(**host_configuration(default_directory, 5)) as runtime:
        token = "Bearer " + (default_directory / "capability").read_text("ascii")
        assert asyncio.run(workflow(runtime, token)).state.value == "Succeeded"

    extended_directory = Path(root) / "extended"
    with open_runtime(
        **host_configuration(extended_directory, 15), execution_timeout_seconds=15,
    ) as runtime:
        token = "Bearer " + (extended_directory / "capability").read_text("ascii")
        assert asyncio.run(workflow(runtime, token)).state.value == "Succeeded"
~~~

This complete checkout example uses synthetic SQLite effects and scripted consent. A consumer
retains its own reviewed provider, executor and receipt store; this is not a real provider pilot.

## Required profile and compatibility rules

- Omission preserves five seconds and legacy compiler/spec/payload identities. Finite
  built-in numbers in `(0, 15]` are accepted; bool/invalid types and non-finite/out-of-range
  values are rejected. Configuration is frozen. Values at or below five only shorten the
  default authority.
- Above five, create a **fresh reviewed base binding revision**, use
  `execution_budget_binding(binding, 15)`, and retain its canonical `.exec-15s` suffix.
  The complete revision must fit 64 characters. Use the same complete binding in capability,
  registry, verifier, policy and consumer receipt store. Retain it across restarts.
- Extended Actions use `action-compiler-v3`/`action-spec-v3`; the exact profile is hashed
  via the binding revision into specification/grant/attempt and `tool-payload-v1` identities.
  Eligibility checks compiler revision and binding before claim. Even old v2 Actions with
  an identical suffix cannot gain authority. Historical validation/recovery remains intact;
  there is no data migration or relabeling of persisted Actions.
- Provision a fresh UUIDv4 scope and private ledger/store identity for the new profile.
  Create a fresh Run, obtain human Plan approval with the profile presented, then admit and
  separately authorize a fresh Action. Do not carry old grants/receipts into a new identity.
  Approval binds the Plan, not a host budget before admission. Retain older schemas/ledgers
  and use their original default configuration for historical work.
- v0.1.0 software cannot interpret new v3 Actions; rollback must retain separate ledgers.
  Default consumers and the local demo remain compatible. The demo cannot opt into an
  extended profile. No general plugin, multi-tool or distributed execution capability is added.

## Guarantees and limits

The trusted maximum is fifteen seconds. The monotonic ToolExecutor deadline starts after
durable claim; a validated caller deadline only shortens it. Invalid caller values fail
before claim; expired or late adapter results become terminal Unknown. Cooperative timeout
and cancellation preserve one-shot claim, CAS, effect identity and durable outcome semantics.
No detached Gateway work, automatic retry, or recovery replay occurs.

Synchronous claim/finish take additional time; a valid on-time adapter receipt retains its
classification when only gate finish is slow. Provider verification and adapter receipt
persistence must fit inside the execution budget. Lost acknowledgements, late receipt handling
and uncertain commits can mean an effect occurred while the Action is Unknown. Finish faults
remain errors/interrupted states for conservative recovery. Blocking Python cannot be
preempted, and neither timeout nor local fencing provides universal remote exactly-once,
distributed HA, malicious-Python isolation, or production human authentication.
The bundled Action HTTP routes retain a ten-second parent deadline. Refund Sentinel's own
transport must reserve enough request time for the fifteen-second adapter plus claim/finish,
and pass only a shortening monotonic deadline to the Runtime Gateway.
